RLDX-1:以「靈巧操作」為核心的
機器人基礎模型

RLWRLD 提出的 Vision-Language-Action 模型,主張現有 VLA 缺的不是語意理解,而是動作感知、長期記憶與物理感測三種功能性能力。本文逐節拆解它的架構、訓練流程與實驗結果。

Dongyoung Kim 等 68 位作者 RLWRLD v1: 2026-05-05 程式 Apache-2.0 · 權重 非商用

一句話總結

RLDX-1 把「認知」、「動作」、「物理訊號」拆成三條獨立的 token 流,只在 joint self-attention 交會,再加上動作、記憶、物理三個可插拔模組;因此它能在有觸覺/力矩時吃進這些訊號,也能在沒有時把那條流整個遮掉,而不動到其他部分。

在 LIBERO、SIMPLER、RoboCasa、GR-1 等模擬 benchmark 上全面超越 GR00T N1.6 與 π0.5;真實機器人則在 OpenArm、ALLEX、Franka FR3 三個平台驗證。

01

研究動機:VLA 還缺什麼

近年 VLA 模型從預訓練視覺語言模型繼承了「通用智能」——廣泛的場景理解與語言條件泛化。論文的出發點是:這種通用性不足以應付真實世界的複雜任務,因為還缺三類功能性能力:

動作感知 (motion awareness)
物體在動、環境在變時,單張影像看不出速度與方向。
長期記憶 (long-term memory)
「把盒子裡沒挑過的物件拿出來」這種任務,答案不在當前畫面裡。
物理感測 (physical sensing)
接觸豐富的操作需要力矩與觸覺,視覺看不到握力與重量。

RLDX-1 的主張是:這三件事應該由架構層級解決,而不是靠更多資料硬學。

02

整體設計

輸入端有四種模態:多幀影片、語言指令、本體感覺 (proprioception)、以及物理訊號 (力矩/觸覺)。它們先經過 VLM 得到認知特徵,再送進 Multi-Stream Action Transformer (MSAT) 產生動作。

輸出是 16 步的動作 chunk,以 flow matching 訓練;若啟用物理模組,還會額外預測未來的物理訊號作為輔助目標。

03

VLM 主幹與認知 token

主幹是 Qwen3-VL 8B,並用一份機器人專用 VQA 資料集微調,涵蓋空間關係、中間子任務、低階動作接地三類問題。論文提到這份 VQA 微調把成功率從 57.5% 提升到 60.9%。

認知 token (cognition tokens)

作者在輸入序列後面附加一組可學習的 query token(預設 64 個),專門用來從 VLM 抽取「與動作相關」的表徵。這組 token 是 VLM 與動作模型之間唯一的窄介面。

取中間層,不取最後一層

特徵取自 LLM 的中間層而非最終層,理由是高層已經為語言生成特化。消融實驗顯示第 18 層效果最好。

影片 token 壓縮

多幀觀測先依時間順序通過前幾層 LLM 累積上下文,之後「保留當前幀,並把過去的觀測用 average pooling 壓成單一 context token」。壓縮放在第 4 層之後(而非第 2 層),以保留 Qwen3-VL 的 DeepStack 多層特徵融合設計。

Qwen3-VL 8B 64 cognition tokens 中間層第 18 層 影片壓縮於第 4 層後 robot VQA 微調 +3.4pp
04

MSAT:多流動作轉換器

這是全篇最核心的設計。MSAT 借用 FLUX 的 MMDiT 概念,把不同模態各給一條獨立的 token 流,再用 joint self-attention 讓它們互通:

  • VL 流:投影後的認知 token,加上(可選的)VLM 原始 hidden states。
  • SA 流:加噪的動作 chunk 與狀態 token,預設用 RoPE 位置編碼。
  • P 流:僅在 use_physics=True 時存在,承載投影後的物理 token。

每個 block 做 modulated pre-norm → 跨串接流的 multi-head self-attention → SwiGLU MLP。前段是三流 block,後段收斂成雙流 block。

關鍵性質 — 因為三條流只在 attention 交會,論文明確指出「當物理訊號不可用時,我們可以把 attention 運算遮掉來停用 P 流」。這就是沒有觸覺/力矩硬體時仍能使用此模型的架構基礎:P 流不是依賴,而是對等的第三條路。

跨形體的動作頭

MultiEmbodimentActionEncoder 把 (B, horizon, max_action_dim) 映射到共享潛在空間,再由各類別的 decoder 投影回去;每個 embodiment index 對應一個線性頭,因此單一 checkpoint 可支援多台機器人。max_state_dim 為 64,物理訊號同樣 pad 到這個維度。

05

三個可插拔模組

對應第 1 節的三項缺口,各有一個模組。三者都是可選的,在 mid-training 階段才引入,預訓練 checkpoint 中處於休眠狀態。

motion awareness

Motion Module

把時空自相似性(space-time self-similarity, STSS)算進視覺編碼器的中間層,以殘差方式更新影片特徵。做法是計算每個時空特徵與其局部鄰域的相關性,得到 STSS 張量後再經 STSS encoder。

置於 27 層視覺編碼器的第 9 層之後 — 作者觀察到物理相關線索出現在約 30% 深度
long-term memory

Memory Module

維護一個顯式的認知特徵佇列,每 H+1 個 timestep 快取一次;佇列與當前特徵串接後過一個 causal-attention 的輕量 Transformer,產生記憶特徵。原始與記憶增強的特徵都會送進動作模型。

佇列長度 nmem=3;時間窗 ALLEX 120 步、FR3 48 步
physical sensing

Physics Module

把力矩與觸覺當成原生模態投影成 P 流。除動作外,還以 flow matching 預測未來 L 步的物理訊號作為輔助目標,促使模型內化接觸動力學。

ALLEX 用關節力矩;FR3 用力矩 + AnySkin 觸覺。不可用時遮掉 attention 即可
對無觸覺硬體的意義 — 物理模組只在 mid-training 出現,從未參與預訓練。也就是說預訓練表徵本身不依賴物理訊號;RLDX-1-PT 的 model card 也說明 memory / motion / physics 三者在該 checkpoint 中為 dormant,只有在微調時接上對應 flag 才會啟用。
06

合成資料框架

這是論文中貢獻很大但未隨程式碼釋出的部分。分兩階段:

階段一:生成

  1. 場景增強 — 用 FLUX.2-dev 做 image-to-image 編輯(以 Canny edge 為條件),改變桌面外觀、物件身份、光照與背景。
  2. 任務增強 — 用 VLM 合成新指令,兩種策略:分解式指令組合(拆成行為/目標/放置位置/手),以及技能原語條件的變化。
  3. 影片生成 — image-to-video 模型產生影片,可再用 video-to-video 轉換增加多樣性。
  4. 動作標註 — 用逆動力學模型 (IDM) 預測動作標籤。

階段二:過濾

  • 影片品質過濾 — VLM 以 1–5 分評判指令遵循度與軌跡合理性(深度感知、空間方向)。
  • 運動一致性過濾 — 在模擬器中重播 IDM 預測的動作,渲染出 rollout 影片與合成影片比對;以 V-JEPA2 embedding 上訓練的 attentive probe 預測對齊分數,超過門檻才保留。

效果:合成資料讓 GR-1 Tabletop 相對「僅用真實資料」提升 9.1%;合成比例從 0% 提到 100% 時,tabletop 表現由 41.0% 升至 50.1%。

推論最佳化

8B 級模型要跑到即時控制頻率,論文用兩招:

  • 靜態圖 (CUDA Graph) 捕捉 — 把 forward pass 錄成單一 CUDA Graph,消掉 kernel launch 開銷(圖 9)。提供 submodule 與 fullgraph 兩種編譯模式。
  • 算子融合 — 自訂 kernel 把資料搬移與運算協調在一起,降低 short-prefill 工作負載的記憶體流量(圖 10)。
RTX 5090 上的單步延遲。另有 Real-Time Chunking (RTC) 兩種變體:guided(訓練無關、需 autograd)與 trained(checkpoint 已針對延遲前綴預訓練,較快且相容 fullgraph),用來讓相鄰 action chunk 銜接平滑。

重點整理與限制

三個最值得帶走的設計

  1. 流的分離讓模態變成可選。這不只是工程便利 —— 它讓同一個預訓練模型能服務有/無觸覺的兩種硬體,而不需要兩套權重。
  2. 記憶用顯式佇列而非隱狀態。佇列 + causal Transformer 比 RNN 式隱狀態更容易控制與重置(部署時需在 episode 開始傳 reset_memory 並維持穩定 session ID)。
  3. 合成資料的過濾比生成更關鍵。用模擬器重播 IDM 動作再比對影片,是很紮實的一致性檢查。

論文本身的限制

  • 沒有明確的 limitations 章節。
  • 真實機器人實驗未給出每個任務的示範數量,難以判斷資料效率。
  • 圖 14 等部分結果只有圖、沒有數值表。
  • 貢獻很大的合成資料管線與 RL 精修程式碼未隨 repo 釋出。
  • 沒有與 GR00T N1.7 比較。
  • 權重採 RLWRLD Model License v1.0:僅限非商業,且衍生模型需沿用同等限制。
