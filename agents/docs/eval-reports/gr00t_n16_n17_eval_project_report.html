1. 結論摘要

  1. N1.7 進步的主因是「相對(delta)手臂動作表示法」——已用單變數 ablation 證實。 同一份新 code、LR=1e-4、150k step,只把 arm 從絕對改回相對:絕對 76% → 相對 89%;且絕對版 76% ≈ 舊 repo 絕對版 77%,排除了新 code 其他變動的作用(見 §3)。
  2. N1.7 需要比 N1.6 更小的 learning rate。 同一份新 code 下,LR 5e-5 明顯優於 1e-4 (150k:98% vs 89%;300k:100% vs 88%);而 N1.6 在 1e-4 已有 94%。
  3. train loss 不是閉迴路成功率的指標。 loss 最低的是 N1.6(0.0030)卻不是最高成功率; N1.7 相對動作版 loss 反而更高(0.0103)成功率卻更好。改了動作目標表示法後,loss 根本不可跨版本比較。

3. 受控比較 A — 動作表示法是主因(已用 ablation 證實)

單變數 ablation(2026-06-16,definitive): 用同一份新 code、LR 1e-4、150k step, 只把 arm 動作從相對改回絕對重訓(N1_7_fft_0615_150k_lr1e4_absolute)→ 成功率 相對 89%(0614)掉到 絕對 76%(0615)。 而 0615 絕對(76%)≈ 0504 舊絕對(77%)→ 新 code 的其他變動(dataloader / stats / warmup / shard) 單獨並不能提升成功率;相對(delta)手臂動作表示法才是那 +13 點的來源。

另有一組舊→新對照(N1.7-150k 舊 0504 絕對 77% vs 新 0614 相對 89%)也指向同一結論; 兩者 base model、dataset、LR(1e-4)、steps(150k)、batch、freeze、state_dropout(都 0.2)相同 (逐項比對 finetune_params.txt 與 baked conf.yaml),只差 arm rep 與兩個次要項(warmup、shard_size)。 上面的 0615 ablation 把那兩個次要項也一併控制掉,所以結論不再有歧義。

「舊=絕對、新=相對」的 config 證據(與 ablation 互相印證)

  1. finetune_params 顯示 modality config 換了: modality_config_right_only.py(舊)→ openarm_o6_config_right_only.py(新)。
  2. repo commit: 新的 OpenArm-O6 config 由 c35bd6e(2026-05-30)、2c755ba(05-31) 加入,晚於 0504 那次訓練,所以舊 run 不可能用到它。
  3. 程式碼自述用途: openarm_o6_modalities.py 明文寫著 「arms → RELATIVE(delta from current joint state;N1.7 generalizes better with relative); hands → ABSOLUTE(像夾爪開合)」。
  4. 原始 config 檔(最直接): 舊 run 用的 Isaac-GR00T/examples/Openarm_LinkerHandO6/modality_config_right_only.py 明寫 right_arm → rep=ActionRepresentation.ABSOLUTE(且 right_hand 也是 ABSOLUTE); 新的 openarm_o6_modalities.py 的 _ARM_ACTION 為 rep=RELATIVE(hand 仍 ABSOLUTE)。
  5. checkpoint 內 baked 的 resolved config(鐵證): 直接 diff 兩個 checkpoint 的 experiment_cfg/conf.yaml(預設值已 resolve)——modality_keys=[right_arm, right_hand], 其 action_configs 第一筆(right_arm)的 rep 在舊=ABSOLUTE、新=RELATIVE。 這是各 run 實際訓練時烤進權重的設定,最可靠。
更正紀錄: 早先曾以 statistics.json 多出 relative_action 區塊來推論, 那其實只是新版 stats 計算的輸出,不足為證(已從證據鏈移除)。以上以原始 config + baked conf.yaml 為準。
結論: 把手臂動作從「絕對關節目標」改成「相對 current state 的 delta」是 N1.7 進步的主因。 這是模仿學習(behavioral cloning)中已知的強力槓桿,理由見 §6。

4. 受控比較 B — N1.7 需要更小的 learning rate

在同一份新 code、同一動作表示、同步數下,只變 LR:

stepsLR 1e-4LR 5e-5差
150k89%98%+9
300k88%100%+12

兩組獨立對照都指向同一方向:N1.7 在 LR 5e-5 明顯優於 1e-4。 而 N1.6 在 LR 1e-4 已達 94% (它的最佳 recipe),不需要降。所以工程準則是: fine-tune N1.7 時用比 N1.6 更小的 learning rate(此處 5e-5,N1.6 用 1e-4)。 直覺上,N1.7 換了更大的 VLM backbone(Cosmos-Reason2 / Qwen3VL),對 projector / diffusion head 的 學習率更敏感,過大的 LR 會擾動已對齊的表徵。

這是兩點對照(150k、300k)歸納的工程結論,方向一致、效果量大(+9 / +12,遠超 100-eps 約 ±3–4% 的抽樣噪音); 若要更細的最佳 LR(例如 7e-5 / 3e-5)需再掃。

5. 受控比較 C — 訓練步數幾乎不影響

同 code、同 LR,150k 對 300k:

  • LR 1e-4:150k 89% vs 300k 88% → 幾乎相同。
  • LR 5e-5:150k 98% vs 300k 100% → 差 2 點,落在抽樣噪音內。

把步數從 150k 加到 300k 沒有帶來有意義的提升。 真正的槓桿是動作表示(§3)與 LR(§4),不是更長的訓練。 150k step 對此任務已足夠。

6. 為什麼 train loss 不是指標

六個 checkpoint 的 final loss(0.0030 ~ 0.0103)與成功率沒有單調關係:

  • loss 最低的是 N1.6(0.0030),成功率 94%,不是最高。
  • N1.7 相對動作 LR1e-4 的 loss(0.0103)比舊絕對動作(0.0077)更高,成功率卻從 77%→89%。

兩個原因:

  1. 改了動作目標,loss 不可跨版本比較。 train loss 是 flow-matching 在「訓練資料動作目標」上的 velocity MSE。絕對動作與相對動作是不同的目標分布,兩者的 loss 數值本來就不可直接比大小—— 所以「相對版 loss 較高」完全不代表它較差。
  2. 相對動作天生對閉迴路更友善。(a)相對 delta 對絕對位置不變,policy 學的是「從現在狀態做小修正」; (b)目標值接近 0、分布更集中,較好擬合且數值條件好;(c)閉迴路 rollout 時能抑制誤差累積 / drift。 這些改善的是閉迴路行為,不必然降低訓練分布上的 loss。

正確的訊號層級仍是:train loss(只當發散哨兵)→ held-out open-loop action MSE → closed-loop success(最終真理)。

7. 限制與驗證實驗

真正的差異(直接 diff 兩個 baked conf.yaml,預設值已 resolve):

  • right_arm action rep:ABSOLUTE → RELATIVE(主因,§3)。
  • warmup_ratio 0.05 → 0.1;shard_size 1024 → 2048(次要)。
  • 相同(已排除為原因): LR(1e-4)、steps(150k)、dataset(0403)、global_batch(32)、freeze 設定、 state_dropout_prob(兩者都 0.2——舊 run 是吃預設值,非差異)。

關於 eval / open-loop / early-stopping 那批 commit(0605–0608): 對訓練出的權重沒有影響—— 0614 的 conf.yaml 顯示 train_episode_indices: null / val_episode_indices: null (沒有切走任何訓練 episode)、early_stopping_patience: 0(關閉),且 eval_strategy=no; 那些是純監控功能,不改權重。

結論已被 ablation 鎖定: 0615(新 code、只把 arm 改回絕對)把 warmup / shard_size / 626af89 等 全部一起控制住,成功率掉回 76% ≈ 舊絕對 77% → 這些都不是主因,arm rep 才是。 唯一沒被獨立切開的,只剩 warmup / shard_size 對「相對動作」可能的微小加成(89% 與 76/77% 的差距太大,不影響主結論)。

驗證實驗狀態

  1. ✔ 已完成(關鍵 ablation): 新 code、LR 1e-4 / 150k、arm 改回絕對 (N1_7_fft_0615_150k_lr1e4_absolute)→ 76%(vs 相對 89%)。坐實相對動作是主因。
  2. ✔ 已確認: arm rep 改變的 config 證據(原始 config 檔 + baked conf.yaml); state_dropout 兩版皆 0.2(本來就不是候選);eval 基礎設施不改權重(episode_indices=null、early-stop off)。
  3. (可選,未來)細掃 N1.7 最佳 LR(3e-5 / 5e-5 / 7e-5);以及在相對動作上單獨驗 warmup / shard_size(預期影響小)。

8. 評測方法

  • 入口:scripts/eval/run_eval.py(讀 configs/eval_config.yaml);每個 checkpoint 收 100 episodes, crash-resilient(server 常駐、client 當掉自動重啟補跑),headless。
  • multitask:每步依 scene_obs.target_object_color 切換語言指令(橘盤 / 綠盤); dataset 0403 僅一台相機,故 pov_list=[head]。失敗幾乎全是 timeout(595 步 horizon),unsafe 極少。
  • 統計可信度:100 eps 的 binomial 標準誤約 ±3–4%;本報告所有結論的效果量都遠超此噪音。
  • 成本參考:headless 下單一 checkpoint 100 eps 約 43 分鐘(RTX 4090)。
