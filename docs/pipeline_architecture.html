IsaacLab-GR00T · N1.7

Fine-tune → Deploy Automation Pipeline

One resumable command waits for a free H100, fine-tunes GR00T on the remote Pegasus box, pulls the verified checkpoint home, hops Wi-Fi to deploy it onto the asus-4090 sim box, and writes an offline report — surviving any disconnect along the way.

IDLE → GPU_WAIT → TRAINING → DOWNLOADING → DEPLOYING → REPORTING → DONE
control flow data flow (animated = live) Wi-Fi switch read-only monitor

One entry point, reused parts

gr00t_pipeline.py is the single CLI. It is a thin dispatcher: every subcommand calls the same function the matching standalone tool uses, so there is exactly one implementation of each behavior — nothing is reimplemented.

Stage by stage

gpu_monitor.py

GPU_WAIT

Polls nvidia-smi on Pegasus until a GPU is idle (util<10% & mem<5 GB). gpu_priority orders candidates (e.g. prefer GPU 1); force_gpu hard-pins one.

training_monitor.py

TRAINING

Launches the fine-tune detached (setsid+nohup) so it survives a laptop disconnect, then tails run.log into metrics.jsonl. On resume it re-attaches if still running, else relaunches and the HF Trainer auto-resumes from the last checkpoint.

downloader.py

DOWNLOADING

Pulls the zipped checkpoint home over HTTP range requests — resumable and sha256-verified, so a dropped connection never leaves a corrupt file.

deployer.py · net_util

DEPLOYING

Switches Wi-Fi to the OMAP LAN, then SFTP-pushes the checkpoint to the asus-4090 over paramiko SSH and unzips it remotely. Retries on transient SSH/network errors.

report_generator.py

REPORTING

Writes an offline report_*.html with run metadata and an inlined Chart.js loss curve (full curve across resumes) — no external assets, opens anywhere.

net_util · finalize

↩ back online

After deploy, restores internet by dropping the LAN and letting the enterprise SSID auto-reconnect — verified by ping, not by the flaky netsh SSID read; warns loudly if it cannot.

Why it survives disconnects

Resumable state machine

pipeline_state.py persists progress to pipeline_state.json after every stage transition. Re-running run re-enters state.current: completed stages are skipped, the interrupted one retries. Training keeps running on Pegasus the entire time.

Resumed loss curve

Each --resume relaunch writes a fresh run.log holding only post-resume steps. The monitor reads every segment in order to rebuild the full curve and tags each point with a segment index, so the dashboard draws step 0→now and changes the train-loss color at every resume boundary.

Stop semantics

stop (or the dashboard's Stop button) kills the detached server job by matching its output_dir in the process argv, then calls PipelineState.stop() so status honestly shows stopped. A later run resumes from the last checkpoint; run --reset starts over.

Network hand-off (the Windows quirk)

A manual netsh wlan connect to the enterprise SSID needs elevation, and netsh can't read the current SSID without Location access. So net_util never relies on that connect: to go online it disconnects the LAN and lets the system auto-reconnect, confirming with ping — and warns loudly if the internet is still unreachable so you can switch manually.
